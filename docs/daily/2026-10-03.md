# 2026-10-03

## 検討: テロップ読み取りを OCR にするか Vision-LLM にするか

- 論点: 画面の日本語テロップ（材料・分量）を読む処理を、OCR（Tesseract/PaddleOCR等）に任せるか、Vision対応LLMに任せるか。
- 結論: **Vision-LLM を採用（OCRにしない）**。
- 理由:
  - 料理ショートのテロップは装飾フォント・縁取り・背景ありで、ローカルOCR（特にTesseract）は精度が落ちやすい。
  - OCRは「玉ねぎ」「1/2個」をバラバラの文字列として出すだけで、**材料と分量の空間的な対応付け（文脈）が失われる**。レシピ化の肝はここ。
  - マルチモーダルLLMは内部でOCR相当＋レイアウト理解＋構造化を1ステップで行い、書き方のゆらぎを文脈で吸収できる。
  - 今回はショート＝フレーム少 + Gemini無料枠なので、OCR導入の主目的（画像トークンのコスト削減）が不要。
- 将来の見直し条件:
  - コストが問題化したら「OCR → テキスト → 安いテキストLLM」を再検討。
  - Visionが分量を読み落とすなら、まず `FRAME_LONG_EDGE` を上げて画像を鮮明化 → それでもダメなら pro 系モデルへ。
