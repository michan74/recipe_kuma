# プロダクト方針・差別化（ハッカソン提出）

SNS動画→レシピ抽出は競合あり（例: 献立ボックス）＝土俵。差別化は「抽出の質・信頼・自律性・実用」で作る。
審査軸に対応: ①新規性・有効性 ②自律性・可観測性・セキュリティ ③実装品質・拡張性・費用対効果。

## ひとことで
**「ただ文字起こしするのではなく、分からない所を自分で見直し、根拠つきで示す“信頼できる自律レシピエージェント”」**
— 特定秒の再視聴・自己批評ループ・証拠提示を実インフラ(Cloud Run)で回す＝単発プロンプトのChatGPTでは出来ない。

## 背骨 C: 証拠つき・信頼（確定）
- 各材料/手順に**出典の秒数 + その瞬間のサムネ(抽出フレーム)**を付与。
- 秒数タップ → **YouTube埋め込みがその秒から再生**して自分で確認（`embed/ID?start=秒`）。
- 「分量=テロップ(0:12)」「切り方=動画で確認済み」など**根拠ラベル/確信度**を表示。
- = エージェントが自分の仕事を証拠つきで見せる（可観測性＝審査②）。秒数データは抽出済みで実装可能。

## 処理の自律性（確定・既存2パスを主役化）
- 2パス: 不明な工程を自分で判断 → その数秒だけ動画で再視聴 → 必要なら人に確認 → 証拠つきで出力。
- 「ChatGPTでは無理」の核。

## 実用 B（確定）
- **代用提案（主役）**: 身近でない調味料が無い時の代替をLLMが提案。
- **人数スケール（おまけ）**: 分量を人数ぶんに調整。

## D: 効率と可観測性（余力）
- Cloud Trace / Logging でエージェントの各ステップを可視化（審査②③）。
- コスト設計（media_resolution / キャッシュ / 不明時のみ動画）を「意図的設計」として提示。
- ※ Gemini Nano は構成と噛み合わず今回は不採用。
