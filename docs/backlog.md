## 精度: 切り方（調理手法）の取得

- 静止フレームでは「切り方」などの**動作(モーション)**を取得しきれない（1枚の静止画に動きの情報が無い）。
- 案A: **Geminiに動画そのものを渡す**（モーション+テロップ+音声を見られる。ショートは小さく現実的。ただしトークン/無料枠の消費増・Files API実装要・コスト要測定）。
- 案B: フレーム密度を上げる（`SCENE_THRESHOLD` 0.3→0.2）。切る前後の静止画は増えるが動きは依然不可。
- 案C: 現状維持（切り方は粗い表現で妥協）。
- 判断: 精度 vs コストで要検討。まずBで粘れるか見て、足りなければAへ、が手堅い。

### 案A-改: 「不明箇所だけ短クリップ動画で再判定」2パス方式（有力）

トークン最小で切り方を取るための設計。

- **パス1**: 各フレームに秒数ラベルを付けて送る（ffmpeg `showinfo` の `pts_time` を取得）。
  出力スキーマに `clarify: [{seconds, reason}]` を追加し、「静止画では動作が判断できない工程の秒数」をモデルに返させる（最大2〜3件）。
- **パス2**（clarifyがある時だけ）: 各秒数の前後だけ ffmpeg で短クリップ（例 `[t-2s, t+2s]`）を切り出し、
  動画としてGeminiに渡して該当手順を具体化 → レシピにマージ。
- 利点: 動画は不明箇所の数秒だけ＝コスト最小。静止画で足りる動画はパス1で完結。
- 実装の勘所: フレーム↔秒数の紐付け / LLMに動作系工程を申告させる指示 / 2回目呼び出し・クリップ切り出し・マージ / 動画はFiles API経由。
